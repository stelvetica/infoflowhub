# 新闻-标的池影响分析

三段式流程：脚本抽标的池与新闻（含当天公告清单）→ AI 维护标的信息库 → AI 产影响分析 → 脚本按有无池内标的重排。完全独立于 portfolio-classify-weight，自带从持仓 Excel 抽取标的池的能力。

| 新闻影响分析 | `<产物根>\新闻影响分析_YYYY-MM-DD.md` |

| 新闻源 · 当日公告清单 | `<产物根>\公告清单_YYYY-MM-DD.md` |

产物根固定指向**主 checkout 的 infoflowhub**（数据与运行实例都在主 checkout，不是 worktree）。

## 新闻源口径

- 新闻源 = **全部"资讯"类源**：Alpha派蓝宝书（`alphapai_markdown`）+ 韭研公社韭菜团子 + 韭研公社韭韭八十一（同在 `jiuyangongshe_markdown`）+ 当天《公告清单》（见本节目录最后一条）。
- **韭研公社两源的正文 markdown 由 infoflowhub 侧下载落盘，本 skill 只读不下载**；目录不存在或为空时脚本跳过并在输出中标注，不阻塞。
- 两类源的解析方式不同但**处理口径一致——都按条切成热点**：蓝宝书按编号条目切分；韭研文章（公社内容精选 / 学习笔记）按「段落块 + 标题行/正文块配对」切分——公众号模板语与运营行、短分组标签（如「一些个股逻辑：」）、尾部传送门之后的内容自动丢弃，编号要点并入所属条目。
- **韭研条目自带原文链接**：infoflowhub 落盘的韭研 markdown 保留了 `[文章标题](原文地址)`（公社内容精选本质是带链接的文章清单）。skill 把链接提取为热点小节里的 `- 原文：[标题](url)` 行，**标题与正文本身不带链接语法**（避免标题被 URL 撑长、影响切条判定）。
- **取新闻只认「上个交易日收盘后」这个窗口**（蓝宝书与韭研公社一致）：窗口内发布的全取，不设条数配额；盘前/盘中发的旧版、隔日放着的内容讲的是市场已消化的事，进分析就是噪声。窗口起点 = 上个交易日 15:00 收盘，交易日由蓝宝书「晨会版 / 午间版」文件名日期反推（这两种版本只在交易日刊出，故不依赖硬编码节假日表；无该证据时退化为「最近一个已收盘工作日」并在输出里标注）。**窗口内没有新内容的来源整源跳过，不降级取更早的条目**，剔除情况写进《今日新闻.md》与 stdout。
- 校验规则：**窗口 = 上个交易日收盘后（窗口内全取）+ 全局至少 1 条为今日**（"源"按 md 头 `- 来源:` 分：蓝宝书 / 韭菜团子 / 韭韭八十一互不挤占；韭研不按源分别要求今日，否则会把流程卡死）。
- **公告清单是补充新闻源，但只吃清单内已筛出的条目**：读当天的 `公告清单_YYYY-MM-DD.md`，表格每行转一条热点（标题带 `公司名（代码）`，正文含公告日期/类型/AI 补的介绍，链接收进 `- 原文`）。**整表纳入，不再按新闻窗口二次过滤**——清单自身已按「自上次运行以来」过滤去重，补收的漏跑日公告也必须进分析。**不重拉原始公告、不复用公告脚本正则**：P0 过滤与衍生件去重已在 portfolio-announcements 完成。当天清单不存在时跳过并在《今日新闻.md》标注，不阻塞；**晨间流程必须先跑 portfolio-announcements，再跑本 skill**，否则清单缺失或介绍仍是"待补"。

## 流程索引

1. **抽标的池**（脚本）：运行 `scripts/extract_pool.py` 生成 `标的池.json`。
2. **取新闻**（脚本）：运行 `scripts/collect_news.py` 生成 `今日新闻.md`（热点合并清单，含当天公告清单）。
3. **维护信息库**（AI）：读 `references/info-template.md`，基于标的池增量更新 `标的信息库.json`。
4. **产影响分析**（AI）：读 `references/impact-template.md`，基于新闻+信息库产出 `新闻影响分析_YYYY-MM-DD.md`。
5. **事件排序**（脚本）：运行 `scripts/order_impact.py <该 md>`，有池内标的的事件排前、无的排后并连续重编号；晨间编排在步骤 7 回写前还会幂等再跑一次，模型漏跑也不会错序。
6. **输出框速览**（AI）：在对话回复里附「中强影响标的速览」（口径见"输出质量"，md 结构不因此改动）。
7. **回写观察目录**（脚本）：运行 `<infoflowhub>\scripts\publish_reports.py`，把最新一套新闻/公告产物复制到观察目录。
8. **打开产出**（AI）：完成后自动打开该 md，固定用 marktext、不走系统关联（`python -c "import subprocess; subprocess.Popen([r'C:\Users\ETT\AppData\Local\Programs\marktext\marktext.exe', r'<绝对路径>'])"`；marktext 缺失则报错停止，不回退 startfile）；**临时 HTML 一律不打开；若任何环节被迫打开了页面，必须立即关闭**。

## 数据流

```
持仓Excel ─[脚本1]─→ 标的池.json ──────────────┐
                                                ├─[AI 维护]→ 标的信息库.json (持久，in_pool 标注)
各资讯源最新新闻 ─[脚本2 热点合并]─→ 今日新闻.md ┤
当日公告清单 ─────[脚本2 并入]─────↗            └─[AI 分析]→ 新闻影响分析.md (仅 in_pool=true 参与)
                                                              └─[脚本3]→ 有标的事件排前、重编号
```

**职责边界**：脚本做确定性抽取（标的池/新闻收集），AI 做主观维护与判断（信息库/影响分析）。`in_pool=false` 的标的信息保留但不参与影响分析。

## 阶段一：脚本抽取

### 1.1 抽标的池

```powershell
python "<skill_dir>\scripts\extract_pool.py" "C:\Users\ETT\Playground\infoflowhub\data\标的观察\持仓标的.xlsx" -o "C:\Users\ETT\Playground\infoflowhub\data\reports\标的池.json"
```

`<skill_dir>` 需替换为 skill 实际绝对路径；模型应自行拼出，不要原样粘贴占位符。

> **默认路径固定为 `C:\Users\ETT\Playground\infoflowhub\data\标的观察\持仓标的.xlsx`，启动即用，无需向用户确认路径。** 仅当用户显式指定其他路径或文件读取失败时才报告错误。

**Excel 列约定**（与 portfolio-classify-weight 一致）：

| 列索引 | 字段 |
|---|---|
| 0 | 产品名 |
| 1 | 股票代码 |
| 2 | 股票名称 |
| 6 | 仓位比例（0–1 浮点；≤0 视为空仓） |

**输出**：`标的池.json`，含 `as_of`/`product_order`/`count`/`stocks`（每只含 `code/name/holders/max_weight`），按 `max_weight` 降序。

### 1.2 取新闻

```powershell
python "<skill_dir>\scripts\collect_news.py"
```

无参数即用默认值：只取上个交易日收盘后发布的新闻（两个源一致，口径见"新闻源口径"），并自动并入输出目录下当天的 `公告清单_YYYY-MM-DD.md`，输出 `<产物根>\今日新闻.md`。`-d` 可重复指定目录（覆盖默认源），`-o` 指定输出路径，`--announcements <路径>` 指定公告清单、`--no-announcements` 关闭公告纳入。

**校验规则**：所选集合中文件名起始日期 = 今日的条数 ≥ 1，否则报错停止（全局口径，不按源分别要求）。全部源目录缺失/为空 → 报错停止；单个源目录缺失/为空 → 跳过并在输出中标注。

**输出**：`今日新闻.md`，热点索引 + 合并去重后的热点清单（已剥离新闻大标题/发布时间/来源页/免责声明/作者利益披露等包装信息；标题完全一致的热点脚本自动合并；标题不同但实质相同的由 AI 在阶段三语义合并）。**韭研文章不再整篇一条**：公社内容精选按文章逐条、学习笔记按「板块热议 / 大涨股解析 / 新股研究」的每条切分；**韭研条目带原文链接**，输出为小节内的 `- 原文：[标题](url)` 行（可能多行，来自不同源的同名热点合并时各留一条）。同时把本次消费的文件名追加写入 `<产物根>\used_news.json` 留痕（只写不读）。

脚本改动后先跑离线自检：`python "<skill_dir>\scripts\collect_news.py" --selftest`（内置夹具校验两类韭研文章的切条规则、上个交易日收盘窗口的推导与筛选，不读外部文件）。

### 异常处置

- 脚本执行失败：报告错误并停止，不兜底自写脚本。
- Excel 缺失或读取失败：报告默认路径的具体错误，停止流程。
- 全部新闻源目录缺失或为空：报告路径错误，停止流程。
- 某来源窗口内无新内容：该来源整源跳过（非错误），跳过情况写进《今日新闻.md》与 stdout；此时分析只有其他来源的内容。
- 全部来源都早于上个交易日收盘（典型：交易日 15:00 后重跑、晚间版还没发）：脚本报错停止并列出最新一条的时间，不降级用已被消化的旧版。
- 今日新闻不足 1 条：脚本报错并列出所选文件名，停止流程，由用户排查后重试；不降级取昨日。
- 当天公告清单缺失或为空：脚本跳过公告并在《今日新闻.md》标注（非错误）；需公告参与时先跑 portfolio-announcements 再重跑本 skill。

## 阶段二：AI 维护标的信息库

读 `references/info-template.md` 作为产出约束，基于《标的池.json》增量更新 `标的信息库.json`。

- **路径**：`C:\Users\ETT\Playground\infoflowhub\data\reports\标的信息库.json`（持久资产）
- **增量规则**：已有代码保留原信息；新增代码 AI 补 `main_business`/`industry`/`chains`；池中已移除的代码 `in_pool` 改 `false` 但**不删除**。
- **JSON 示例**：见 `references/pool-example.json` 的 `info_db` 字段。

### 硬约束

- 唯一产出格式 JSON，可被 `json.loads` 解析。
- `in_pool` 字段必填，由标的池成员关系决定。
- 不删除 `in_pool=false` 的标的（保留历史，避免反复进出持仓时重算）。
- `chains` 命名需一致性（同一产业链在所有标的中用同一名称）。

## 阶段三：AI 产影响分析

读 `references/impact-template.md` 作为产出约束，基于《今日新闻.md》+《标的信息库.json》（仅 `in_pool=true`）+《标的池.json》产出 `新闻影响分析_YYYY-MM-DD.md`。

- **路径**：`C:\Users\ETT\Playground\infoflowhub\data\reports\新闻影响分析_YYYY-MM-DD.md`（YYYY-MM-DD 为今日日期；目录由 AI 自动创建；同日多次运行直接覆盖，不加版本号）

### 判定规则要点

**组织单元 = 独立热点事件**（一级结构，须严格遵循）：

1. **一级 `## 事件 N：标题`**：先按《今日新闻.md》热点索引顺序，每个热点一个小节（《今日新闻.md》已是跨源合并的热点清单，不再有"新闻 N"分节）；最终顺序与编号由步骤 5 的排序脚本统一重排。
2. **语义去重**：标题不同但实质为同一事件的热点（同一公司/同一事实/同一逻辑主线，如蓝宝书与韭研都报"芯碁微装获批量订单"、"固态电池标准+免税"）必须合并为一个事件小节，标注 `- 来源：晨会版+韭菜团子`；合并阶段编号可先按原顺序写，最终由排序脚本统一重排。
3. **排序（脚本固化，不靠模型手工排）**：全部事件写完后运行 `python "<skill_dir>\scripts\order_impact.py" "<新闻影响分析 md>"`——有池内受影响标的的事件在前、`池内受影响标的：无` 的在后，两组内部保持原顺序，编号从 1 连续。脚本只读 `- 池内受影响标的：` 行，不改写任何分析内容。
4. **韭研/公告来源的事件必须带原文链接**：把《今日新闻.md》该热点的 `- 原文：[标题](url)` 行原样抄进事件小节（紧跟 `- 来源：` 行；多个来源各自一条）。**不得改写 URL、不得省略**——这是用户点回原文的入口。蓝宝书/无链接热点不写此行。
5. 每条独立事件内判定五要素（影响性质/层级/池内标的/因果/池外观照）；无相关时影响性质写「中性」，标的行固定写 `- 池内受影响标的：无`（排序脚本据此判定，不要写成「池内无」等变体）。
6. 产业链级须指明链条方向与各环节正负向。
7. **仅对 `in_pool=true` 的标的判定影响**，无影响的不列入标的。
8. **池外观照严格按名称判断**——不强行关联池内相似名称的标的（如新闻提"三一重工"，池内有"三一重能"，是不同公司，三一重工列入池外观照）。
9. 影响强度分 强/中/弱，弱影响可省略。
10. 利好/利空必须基于新闻事实与标的主营业务/产业链位置的逻辑推演，不编造。

### 禁止事项

- 不对 `in_pool=false` 的标的做影响分析。
- 不修改标的信息库（本阶段只读不写）。
- 不编造新闻未提及的因果链。

## 输出质量

- 结论先行，少废话。
- 因果说明简短（一行内）。
- 池外观照只列名称不展开。

### 输出框速览（必出，不得省略）

md 落盘后，**对话回复里必须附一段「中强影响标的速览」**，让人一眼看清今天该关注什么：

| 标的（代码） | 方向 强度 | 原因（新闻事实 → 传导逻辑） |
|---|---|---|
| 300408.SZ 三环集团 | 利好 强 | MLCC 全渠道提价 30%–80% 于 10/1 执行，量价与份额双击 |

- **只列 强 / 中 影响的池内标的**；弱影响、中性、池外观照一律不列。
- 排序：强度（强 → 中）优先，同强度按标的池权重降序。
- 「原因」一句话说清"什么新闻事实 → 为什么影响这家公司"，不写套话。
- 当日无中强影响标的时，直接写"今日无中强影响标的"，不硬凑。
- **速览只进输出框，不改 md**：`新闻影响分析_YYYY-MM-DD.md` 仍按上文标准（新闻事件角度、事件小节 + 五要素）生成，结构不因速览改动。
