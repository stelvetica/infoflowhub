# 近期操作分析

成交流水 + 估值表 → 行业/个股加减 + 权益敞口变化。**数据由脚本算，AI 只写各产品点评**，两段职责不混。

## 路径约定（默认值，可被用户指令覆盖）

| 用途 | 路径 |
|---|---|
| 运行配置（产品、窗口、行业表） | `C:\Users\ETT\Playground\infoflowhub\config\portfolio_operations.json` |
| 成交汇总 CSV | `C:\预估值_PB系统\数据\交易系统数据\最近_交易系统汇总数据\历史成交汇总.csv` |
| 估值表根目录 | `C:\预估值_PB系统\产品\<产品>\` |
| 产物根 | `C:\Users\ETT\Playground\infoflowhub\data\reports\` |
| 报告 | `<产物根>\操作分析_YYYY-MM-DD.md` |
| 底稿（AI 读它，不读 md） | `<产物根>\操作底稿_YYYY-MM-DD.json` |

产物根固定指向**主 checkout 的 infoflowhub**（数据与运行实例都在主 checkout，不是 worktree）。

## 口径（脚本已固化，勿在对话里临时改）

- **窗口按交易日**：近一周 = 最近 5 个交易日，近一月 = 最近 20 个交易日；交易日取自成交 CSV 自身的日期集合。报告头部会写出实际日期区间，引用数字时连区间一起引。
- **权益敞口 = 股票市值占净值% + 收益互换保证金占净值%**。互换底层均为股票，按股票计入（仅臻享1期有互换）。
- **净值与仓位只取最新估值表**（用户口径：取个大概即可）；所有加减按「占最新净值%」呈现，金额只留在底稿 JSON。
- **回购不计入个股加减**（GC001 等），单独统计。
- **不做「全部产品合计」**：各产品净值规模与策略不同，跨产品百分比加总没有组合含义；行业/个股一律分产品呈现。
- **成交截至报告日、估值截至上一估值日**，净卖出额与仓位变化不完全对齐属正常。
- **FOF 产品按母基金口径**：金享1号自身净值约 591 万，100% 持有母基金「大朴金享」；个股操作与仓位取母基金，脚注写明自身规模。
- **产品清单在 config 里**（当前：臻享1期、金享1号、多维度24号、未来1号），增删产品只改 `config/portfolio_operations.json`。
- **行业表内置在 config 的 `industry_overrides`**（code → [名称, 行业]），不依赖标的信息库；只收录观察产品出现过的标的。新标的出现时归「未归类」进底稿 `unresolved`，由 AI 查证后补进 config 再重跑。

## 流程

| # | 步骤 | 执行者 | 说明 |
|---|---|---|---|
| 1 | 跑脚本 | 脚本 | 读 CSV + 估值表 → 报告 md + 底稿 json |
| 2 | 补未归类行业 | AI | 底稿 `unresolved` 非空时，按公开主营写进 config 的 `industry_overrides`，重跑步骤 1 |
| 3 | 写各产品点评 | AI | 脚本已生成个股/行业/特征/产品分化四段；AI 只填每个产品 0–3 句判断，不重复数字 |
| 4 | 交付 | AI | 对话里给结论摘要；不改表格与脚本生成段落的任何数字 |

> 同日重跑脚本会重置点评（只留占位），重跑后需重写；其余四段每次由脚本重算，无需 AI 维护。

## 调度

每周**最后一个交易日 7:30** 跑一次，由 `web/services/auto_runner.py` 的 `_maybe_run_operations` 触发——独立任务，不进晨间 `SKILLS` 链（否则每天多跑一轮模型）。「最后一个交易日」取本地交易日历，周五休市自动前推到周四；当天没跑成会在当天内补跑，失败当天不重试。状态写 `runtime/health/automation_runtime.json` 的 `slots.operations`。

**运行命令**（无参数全默认；改脚本后先 `--selftest`）：

```powershell
python "C:\Users\ETT\Playground\infoflowhub\skills\portfolio-operations\scripts\collect_operations.py"
python "<skill_dir>\scripts\collect_operations.py" --selftest
python "<skill_dir>\scripts\collect_operations.py" --date 20261104
```

依赖 `openpyxl`（.xlsx）与 `xlrd`（.xls），两者都在 `requirements.txt` 里。

## 阶段二：AI 写作要求

只写 `## 解读` → `### 5. 各产品点评`，替换每个产品的占位注释。其余四段（个股/行业/特征/产品分化）与所有表格由脚本生成，AI 不动。

硬约束：

- **逐产品 0–3 句**：只写判断——这周在干什么、是减仓还是换仓、哪笔值得跟踪；无事可说的产品直接删掉该行，不写套话。
- **不复述表格数字**：上表已有加/减 Top3、换手、集中度、反转；点评里最多引用一个关键数字，其余用「大幅/小幅/集中/分散」这类相对表述。
- **不评价操作对错**：没有成本价与实现盈亏，任何「卖得对/买贵了」都是编造。要评价只能明说「需要成交价与成本基准」。
- **数据异常在对应产品点评里点出**：估值表缺失、净值反推失败、未归类标的——哪只产品的数据有问题就写在哪只产品下，不静默略过。
- **不写跨产品合计百分比**：跨产品只做方向对比，不把百分比相加。

## 异常处置

- 成交 CSV 缺失/为空：报错停止，不兜底。
- 某产品在 CSV 里一条都没有：在报告里该产品留空，并在该产品点评里标注（通常是产品改名或口径变更，先核对 `csv_names`）。
- 估值表某日期找不到：该产品仓位显示「—」并继续，不阻塞；在该产品点评里标注。
- 净值反推失败（既无净值行、也没有股票/基金市值占比）：净值显示「—」，不影响净额统计。
- 全部产品都取不到仓位：报告照出，但必须在点评里说明「仓位段不可用」。

## 输出格式

`操作分析_YYYY-MM-DD.md`：解读（1 个股动向 / 2 行业动向 / 3 交易特征 / 4 产品分化，均由脚本出；5 各产品点评由 AI 写）→ 口径（3 条以内，完整规则见本节）→ 总览 → 仓位 → 近一周/近一月明细（分产品折叠）。

`操作底稿_YYYY-MM-DD.json`：`windows` / `products[].position` / `products[].week|month`（buy/sell/net/repo/industries/stocks/unresolved）/ `total`。AI 只读它，不从 md 反向解析。
