# 持仓 P0 公告监控

脚本做确定性抽取（拉公告+过滤），AI 做主观工作（补介绍/出图/解读）。与 portfolio-news 同构互补。

**晨间顺序：本 skill 先跑，portfolio-news 后跑。** 步骤 3 补完介绍的当天《公告清单》会被新闻分析作为补充新闻源读取（只读清单内已筛出的条目）；步骤 5 先回写一次观察目录，新闻流程结束后会再回写一次，带上当日新闻影响分析。

## 流程

| # | 步骤 | 执行者 | 说明 |
|---|---|---|---|
| 1 | 抽标的池 | 脚本 | 标的池过期时，按 news-portfolio-impact 的 `extract_pool.py` 重新生成 `标的池.json` |
| 2 | 拉公告 | 脚本 | 运行 `scripts/collect_announcements.py` → `公告清单_YYYY-MM-DD.md`（介绍列为"待补"） |
| 3 | 补介绍 | AI | 逐条读公告原文，一句话（含关键数字）填入"待补"格 |
| 4 | 渲染图片 | AI（有 P0 时必做） | 清单转临时 HTML → 截图 `公告清单_YYYY-MM-DD.png` |
| 5 | 回写观察目录最新套 | 脚本 | 运行 `<infoflowhub>\scripts\publish_reports.py`，观察目录只保留最新一套 |
| 6 | 影响解读 | AI 可选 | 结合 `标的信息库.json` 判利好/利空；晨间流程中默认由 portfolio-news 统一分析（本清单已纳入其新闻源），无需重复解读 |
| 7 | 打开公告 | AI（有 P0 时必做） | 完成后打开 `公告清单_YYYY-MM-DD.png`；0 条 P0 不打开 |

**运行命令**（无参数全默认；改脚本后必须先 `--selftest` 再实跑）：

```powershell
python "C:\Users\ETT\Playground\infoflowhub\skills\portfolio-announcements\scripts\collect_announcements.py"
```

默认读 `<产物根>\标的池.json`，输出与留痕写 `<产物根>`；**产物根 = `C:\Users\ETT\Playground\infoflowhub\data\reports\`**（主 checkout 的 infoflowhub，不是 worktree）。路径可被用户指令覆盖。

## 步骤 3：补介绍

- 原文取东财正文接口：`https://np-cnotice-stock.eastmoney.com/api/content/ann?art_code=<art_code>&client_source=web&page_index=1`（每页 5000 字可翻页，A/H 同源）。
- **港股業績公告正文常残缺**（中芯 2026-11-12 三季报实测：前 2 页全是空字节，第 3 页从半张表开始）：改取同日港股侧 `海外監管公告-營運業績最新情況` 的 art_code（正文是 A 股季报全文，内容完整），标题/链接仍用 `季度業績` 那条。
- 正文不足再联网搜索；搜索引擎直连常被反爬挡（Bing 实测），**优先用公告原文**。
- **AI 语义复核去重（第二层）**：补介绍时逐条通读，若发现脚本正则漏剔的衍生件/重复公告（如同一事件两次披露、标题未见过的配套文件），从 MD 清单中删除该行并在回复中说明；正则误剔的（衍生标题含独立实质）也在此层捞回。脚本正则是第一层粗筛，AI 层兜语义。

## 步骤 4：渲染图片

临时 HTML 为**扁平单表**，四列 `公告日期 | 证券代码 | 证券名称 | 公告标题`（标题带链接、不含公司名前缀；A/H 按日期降序混排），中文字体 Microsoft YaHei。**页面不带大标题/来源说明行，只渲染表格本身**。

紧凑无空白规范（CSS 固化，勿改回默认样式）：

- `body{margin:6px}`，单元格 `padding:3px 8px`、单线边框
- 日期/代码/名称三列定宽（约 86/88/96px）单行显示，超长省略
- **公告标题列允许自动换行**（`white-space:normal;line-height:1.35`），不截断标题
- playwright 视口宽度略大于表格宽度，**高度不大于内容高度**，再全页截图——底部不产生大块空白

1. 写临时 HTML → `python -m http.server 8741` 后台起服务
2. playwright **必须 `headless=True`** 打开 `http://127.0.0.1:8741/<编码后文件名>` 全页截图存 PNG（**不弹浏览器窗口**）
3. 截图后**必须 `browser.close()`**；再停 http 服务、**删临时 HTML**（打开动作在步骤 7）

> playwright 禁 `file://` 协议，必须走 http。

**硬约束（用户投诉项，不得放宽）**：

- 生成图片全过程**不打开任何浏览器页面**：playwright 必须 headless，截图完必须 `browser.close()`。
- **禁止 `os.startfile(html)`**；只允许 `os.startfile(<PNG 绝对路径>)`。
- 临时 HTML 与 http 服务是截图中间产物，截图完成即删/即停，不留痕。
- 若因故仍打开了 HTML 页面（如调试），**必须立刻关闭**，不得留在屏幕上。

## 步骤 5：回写观察目录最新套

```powershell
python "C:\Users\ETT\Playground\infoflowhub\scripts\publish_reports.py"
```

- 把 `<产物根>` 下三类产物（`新闻影响分析_*.md` / `公告清单_*.md` / `公告清单_*.png`）各取最新 1 个复制到 `C:\Users\ETT\Playground\infoflowhub\data\标的观察\`，并删除该目录内非最新的同类文件——**观察目录只保留最新一套**。
- 脚本归 infoflowhub 仓库（两个 skill 共用），只操作上述三类文件；`持仓标的.xlsx`、`自选股.xlsx`、`2025十大持仓\` 等一律不碰。
- 先看将做什么：`--dry-run`；改动脚本后必须先 `--selftest`。
- **与新闻流程的先后**：本步骤保证公告单独运行时产物也能落盘；晨间流程中 portfolio-news 会在末尾再跑一次 `publish_reports.py`，把当天新闻影响分析一并刷新进观察目录。

## 步骤 7：打开公告

- **有 P0 条目时必须执行**：`python -c "import os; os.startfile(r'<公告清单 PNG 绝对路径>')"`，打开当天的 `公告清单_YYYY-MM-DD.png`。
- 当天 0 条 P0（清单为空）不生成 PNG，也不打开任何文件。
- **只打开 PNG**：PNG 缺失时先排查渲染失败，不要回退打开 MD 或 HTML。

## 口径与约束（脚本已固化，勿在对话里临时改口径）

- **数据源**：东财公告接口（A/H 同源、免 key、零依赖）；0.2s 间隔 + 失败重试防限流。
- **A+H 孪生通道**（标的池 `hk_code` 字段，A 股标的有同名港股时由 `extract_pool.py` 自动挂，港股已在池中则不挂）：
  - **壳标题借义**：A 股标题为壳（`自愿性公告`/`H股公告`/`海外监管公告`/`公告`/`提示性公告`）时，取港股**同日**描述性标题与类型判类，清单展示港股标题、类型标「（港股）」、链接指向港股通道，只留一行。
  - **港股独有实质类型**（A 股通道无对应物，独立补收）：`其他-業務發展最新情況`、`其他-營運業績最新情況`、`盈利警告`、`董事會召開日期`；同日 A 股已出 P0 则不重复收。
  - **不取**：港股 `海外監管公告-*`（A 股文件副本）、`月報表`、`委任代表表格`、`股東會通告/資料`、`翌日披露報表`、`股份購回`。
- **日期窗口**（自上次运行以来）：A股取 公告日∈(last_run, 今日]（昨晚披露挂今日）；港股取 公告日∈[last_run, 今日]（披露当日即日期）。`last_run` 记录在 `used_announcements.json`，缺省回看 3 天（`--lookback-days` 可调）；去重保证窗口拉长不重复输出——漏跑日（如周一）自动补收周末公告。
- **P0 定义**：能改变持仓判断的新事实——业绩、摊薄、筹码、重大经营、风险监管、分红。判「这条公告里有没有新事实」，不判交易所给它贴了什么标签。

- **判定流水线**（每条公告依次过，命中即止）：

  | # | 层 | 规则 | 结果 |
  |---|---|---|---|
  | 1 | 排除层 | `EXCLUDE` 绿鞋/超额配售；类型 `法律意见书`；港股程序性类型 `海外監管公告-*` / `月報表` / `委任代表表格` / `股東會通告` / `翌日披露報表` / `股份購回` | 丢 |
  | 2 | 类型层 | `columns[0].column_name` ∈ 白名单（下表 A） | P0 |
  | 3 | 标题层 | 标题命中关键词（下表 B），对「其他」类兜底——重要公告大量藏身「其他」 | P0 |
  | 4 | 决议层 | 以「董事会/监事会/股东大会…决议」结尾且不含关键词 | 丢（实质事项另有专项公告） |
  | 5 | 壳标题层 | A 股标题是纯壳（`自愿性公告`/`H股公告`/`海外监管公告`/`公告`/`提示性公告`）时，借港股同日描述性标题与类型判类，清单只留一行、类型标「（港股）」 | 按借来的判 |
  | 6 | 港股补收层 | `HK_ONLY_TYPES` 四类独立补收；同日 A 通道已出 P0 则不重复 | P0 |
  | 7 | 去重层 | 财报/融资/分红三组只留关键公告（见「不收」表） | 留关键件 |

  **A. 类型白名单**（东财实测值，22 个，命中即 P0）

  | 事件族 | 类型 |
  |---|---|
  | 业绩 | 业绩预告、业绩快报、一季度报告全文、半年度报告全文、三季度报告全文、年度报告全文 |
  | 分红 | 分配预案、分配方案实施、分配方案决议公告 |
  | 股东筹码 | 股东/实际控制人股份减持、权益变动报告书、限售股份上市流通、要约收购 |
  | 重大经营 | 重大资产重组 |
  | 港股业绩 | 中期/半年度報告、中期業績、全年業績、季度業績 |
  | 港股独有（仅 A+H 孪生补收） | 其他-業務發展最新情況、其他-營運業績最新情況、盈利警告、董事會召開日期 |

  **B. 标题关键词**（简繁双写，命中任一即 P0）

  | 事件族 | 关键词 |
  |---|---|
  | 风险监管 | 立案、处罚、警示函、监管函、问询、诉讼、仲裁、退市、重整、减值 |
  | 重大经营 | 重组、收购、出售、中标、重大合同、停牌 |
  | 再融资摊薄 | 可转债、可转换、可换股（港股叫法）、可交换（EB）、满足赎回条件、向特定对象发行、配股、增发、配售、供股 |
  | 股东筹码 | 减持、增持、承诺不减持、要约、权益变动、控制权变更 |
  | 分红派息 | 利润分配、分红、派息、股息 |
  | 业绩 | 业绩预告、业绩快报、盈利警告、盈喜、盈警 |

- **不收**：

  | 类别 | 内容 |
  |---|---|
  | 重复/同事件衍生件 | 报告「摘要」；再融资的提示性/论证分析/可行性/摊薄回报/财务资助承诺/审核意见/监管回顾/分红回报规划；分红的实施公告/过户登记/股息公告表格；财报的计提减值/说明会/资金占用汇总表（组内无关键件时保留，不丢信息） |
  | 发行机制 | A 股 IPO 超额配售/绿鞋 |
  | 程序性 | 董事会/监事会/股东大会决议（不含关键词）、法律意见书、公司章程与管理办法、独董系列声明、股东大会通知/资料、月報表、委任代表表格、翌日披露報表、股份購回、港股 `海外監管公告-*`（A 股文件副本） |
  | 转债存续期杂项 | 转股价格调整、停止交易、暂停/恢复转股、到期兑付、持有人会议、受托管理报告（立讯转债到期前后可刷十几次，无摊薄增量） |
  | P1（默认不收，人工可放开） | 股权激励、员工持股、回购、质押冻结、担保、关联交易、对外投资、变更募资用途、审计机构变更、核心高管变动、月度经营数据、调研 |
  | P2（永不收） | 投资理财、章程/议事规则、独董声明 |

- **灰区**（现口径不收，遇标的重大变化时人工判断）：港股 `內幕消息` 下的季度经营数据（信达产品收入、龙源月度发电量）、控股股东一致行动人内部转让暨解除一致行动、股票交易异常波动、须予披露的交易/参与设立基金。
- **去重留痕**：`used_announcements.json` 记已输出的 art_code，重跑不重复；历史条目不清理（年增 KB 级）。
- **护栏**：当日重跑无新增→保留已有清单不覆盖；拉取失败的标的列清单尾部"未取到"，不静默丢弃。

## 异常处置

- 脚本失败：报错并停止，不兜底自写脚本。
- 标的池缺失/为空：先跑 extract_pool.py，仍失败报错停止。
- 提示"无新增、保留已有"：去重生效的正常表现，向用户说明即可。

## 输出格式

`公告清单_YYYY-MM-DD.md`：标的按 max_weight 降序分组，每组一张表 `| 日期 | 类型 | 公告名 | 介绍 |`，公告名带东财详情链接，介绍列为 AI 补的一句话；末尾统计 P0 条数与涉及标的数。有 P0 时必出同名 PNG（四列扁平单表），并在步骤 7 打开。
