# 新闻影响分析 MD 产出约束

基于《今日新闻.md》（脚本已合并去重的热点清单）+《标的信息库.json》（仅 `in_pool=true`）+《标的池.json》，产出《新闻影响分析_YYYY-MM-DD.md》。

## 组织单元：独立热点事件（务必遵循）

**判定与组织的工作单元是独立热点事件；输出一级结构按事件展开，不再按新闻篇分节**（《今日新闻.md》已是跨新闻合并的热点清单，无"新闻 N"分节）。

1. **一级 `## 事件 N：标题`**：按《今日新闻.md》热点索引顺序，每个热点一个小节，编号连续。
2. **语义去重合并（AI 职责）**：脚本仅合并了标题完全一致的热点；标题不同但实质为同一事件的热点（同一公司/同一事实/同一逻辑主线，如"芯碁微装获重复批量订单"与"芯碁微装获批量订单"、"固态电池标准立项"与"固态电池免征消费税"）必须合并为一个事件小节——标题取信息更全版本，正文以最新、最全版本为准，并在小节内标注 `- 来源：晚间版+晨会版`；合并后事件编号重新连续。
3. **韭研来源的事件必须带原文链接**：把《今日新闻.md》里该热点的 `- 原文：[标题](url)` 行**原样**抄进事件小节（紧跟 `- 来源：` 行；多个来源各自一条）。不得改写 URL、不得省略——这是点回公社原文的入口。蓝宝书/无链接的热点不写此行。
4. 每个事件内判定五要素：影响性质（利好/利空/中性）、影响层级（个股性/行业性/产业链级）、池内受影响标的（代码+名称+因果+方向+强度）、池外观照；无池内相关时写明"池内受影响标的：无"，事件小节仍保留。
5. 产业链级须指明链条方向（上游→中游→下游）与各环节正负向；同一事件可同时含利好与利空环节。
6. **仅对 `in_pool=true` 的标的判定影响**，无影响的不列为池内，该事件仍成立。
7. **池外观照严格按名称判断**——新闻提到但不在池内的标的单独列入；**不强行关联池内相似名称的标的**（如新闻提"三一重工"，池内有"三一重能"，这是不同公司，三一重工列入池外观照，三一重能若不受影响则不列）。
8. **影响强度**分 强/中/弱，弱影响可省略不列。
9. **利好/利空必须基于新闻事实与标的主营业务/产业链位置的逻辑推演**，因果说明一行内，不编造。

## 输出示例

```md
# 新闻影响分析 2026-07-07

## 事件 1：6月挖掘机销量同比增长35%超预期
- 影响性质：利好
- 影响层级：行业性（工程机械）
- 池内受影响标的：
  - `601100.SH` 恒立液压（核心零部件供应商，业绩弹性受益）利好 中
- 池外观照（新闻提到但不在池内）：三一重工/徐工机械/中联重科

## 事件 2：AI服务器需求推动电子布CCL持续涨价
- 影响性质：利好（上游）/ 利空（中游PCB短期成本压力）
- 影响层级：产业链级
- 涉及产业链：电子布 → CCL → PCB
- 池内受影响标的：
  - `600183.SH` 生益科技（CCL环节，涨价传导顺畅）利好 强
- 池外观照：无

## 事件 3：某公司先进封装设备获批量订单
- 来源：晚间版+晨会版（语义合并）
- 影响性质：中性
- 影响层级：个股性
- 池内受影响标的：无
- 池外观照：某公司/可比公司
```

## 硬约束

1. 全文中文 Markdown。
2. 每个独立热点事件一个 `## 事件 N：标题` 小节，编号按《今日新闻.md》热点索引顺序且连续；语义重复的事件必须合并为一节并标注合并来源。
3. 池内标的用代码+名称+因果说明+影响方向+强度五元组，一行一个。
4. 池外观照只列名称，用 `/` 分隔，不展开分析。
5. 文末不加总结段落（避免废话）。

## 禁止事项

- 不按"新闻篇"组织小节——一级小节只能是事件。
- 不对 `in_pool=false` 的标的做影响分析。
- 不编造新闻未提及的因果链。
- 不把行情/资金流等与新闻无关的因素纳入判定。
- 不修改标的信息库（本阶段只读不写）。
